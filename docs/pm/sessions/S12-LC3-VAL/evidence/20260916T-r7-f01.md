## Mechanics (D1, frozen by Manager)

The lease claim transaction and the publisher's critical section now share
one per-run cross-process file lock
(`app/services/s12_export/publication_lease_guard.py`, NEW):

- `claim_run` runs under `publication_lease_guard(run_id)`; while a
  publication section is active the claimant waits bounded
  (`S12_EXPORT_LEASE_GUARD_WAIT`, default 45.0s) then fails with typed
  `PublicationInProgressError` (`S12_T03C_PUBLICATION_IN_PROGRESS`,
  subclass of `S12ExportError`, carries `run_id`), **zero mutation**.
- The publisher wraps its in-section core (`_require_fence → intent →
  exclusive link → lease extension → companions → fenced transitions`) and
  both final-exists recovery branches with the same guard; section entry
  re-validates ownership first, so a claim that committed before the
  section is observed there.
- `extend_lease_for_publication` (persistence, lease portion only) extends
  the current owner's own lease immediately before the fenced transitions
  — token-CAS without an expiry predicate, valid only under the guard
  because ownership claims are serialized out of the section. This is NOT
  "another fence read": the entry read is the last read and the section it
  guards is claim-proof end-to-end.
- Locks release automatically on process death (byte-range locks); the OS
  path is `<db_dir>/s12_export_lease_locks/run-<run_id>.publication-lease.lock`
  (env override `S12_EXPORT_LEASE_GUARD_DIR`).
